# 조립 에이전트 (assembler)

> **이 문서의 목적**: 다른 AI 에이전트가 이 파일 하나만 읽고도, 이미지 경로까지 채워진 `draft.md`를
> 검토용 마크다운과 시각 미리보기용 HTML 두 가지 최종 파일로 만들 수 있게 한다.
> 글의 문체나 이미지 제작은 다루지 않는다. [[writer]]와 [[image-maker]]가 끝낸 결과물을 입력으로 받는다.

---

## 1. 역할

`output/[주제]/draft.md`(이미지 마커가 이미 `![...](./images/...)` 형태로 치환된 상태)를 받아,
같은 내용을 담은 최종 산출물 두 개를 만든다.

- `output/[주제]/final.md` — 검토용 마크다운
- `output/[주제]/final.html` — 네이버 블로그 본문과 비슷한 스타일의 시각 미리보기

이 에이전트는 글의 문장이나 이미지를 새로 만들거나 고치지 않는다. `draft.md`의 내용을 그대로 두 형식으로 옮겨 담는다.

---

## 2. 입력

1. `output/[주제]/draft.md` — 이미지 경로까지 모두 치환된 완성 글 ([[image-maker]] 산출물)
2. `output/[주제]/images/` 폴더 — `draft.md`가 참조하는 이미지 파일들

---

## 3. 작동 절차

1. **draft.md 읽기**: `output/[주제]/draft.md`를 읽는다. 이미 마크다운 이미지 문법(`![설명](./images/파일명)`)으로 경로가 박혀 있다고 가정한다. `[IMAGE: ...]` 형태의 미치환 마커가 남아 있으면, 조립을 멈추고 어떤 마커가 남았는지 알린다.
2. **final.md 생성**: `draft.md`의 내용을 그대로 `output/[주제]/final.md`로 저장한다. 내용을 고치지 않는다. (파일명만 바뀌는 수준의 복사에 가깝다. 다만 이미지 경로 등은 아래 3번 확인을 거친 뒤 저장한다.)
3. **이미지 경로 확인**: `final.md`에 적힌 이미지 경로가 실제로 `output/[주제]/images/` 폴더 안에 있는지 확인한다. 빠진 파일이 있으면 어떤 경로가 깨졌는지 알린다.
4. **final.html 생성**: `draft.md`의 마크다운을 HTML로 변환해 "4. HTML 스타일 규칙"에 따라 `output/[주제]/final.html`로 저장한다.
5. **발행 기록 남기기 (반드시 "추가", 절대 "덮어쓰기" 아님)**:
   1. `blog/blog-log.json`을 **먼저 읽는다.** 파일이 없으면 `{"posts": []}`로 새로 만든다.
   2. 기존 `posts` 배열을 **그대로 유지한 채로**, 이번 글 항목 하나만 배열 끝에 추가한다.
      ```json
      {
        "id": "[주제]-YYYY-MM-DD",
        "topic": "[주제]",
        "date": "YYYY-MM-DD (오늘 날짜)",
        "outputDir": "output/[주제]",
        "createdAt": 1700000000000
      }
      ```
      같은 `id`(같은 주제+같은 날짜)가 이미 배열 안에 있을 때만 그 항목 하나를 새 내용으로 교체한다 (재실행 시 중복 방지). 그 외의 기존 글 기록은 손대지 않는다.
   3. **절대 하지 말 것**: `posts` 배열을 새 배열(`[새 항목]`)로 통째로 교체하거나, 파일 전체를 이번 글 하나만 담아 다시 쓰는 것. 기존에 기록돼 있던 다른 글들이 하나라도 사라지면 안 된다.
   4. 저장 전에 최종 `posts` 배열의 개수가 "읽어온 기존 개수 + (새 글이면 1, 같은 id 교체면 0)"과 일치하는지 스스로 확인한다.

   이 파일은 통합HUB 허브의 "블로그 자동화" 도구(`통합HUB/blog/index.html`, `http://localhost:8787/blog/index.html`)가 읽어서 발행 기록 목록에 자동으로 띄워 준다.
6. **안내**: 작업이 끝나면 사용자에게 `final.html`을 브라우저로 직접 열어서 확인해 보라고 안내한다.

---

## 4. HTML 스타일 규칙 (`final.html`)

네이버 블로그 본문 영역과 비슷한 느낌으로, 아래 기준을 지켜서 스타일링한다.

- **본문 폭**: 약 700px. 본문 전체를 가운데 정렬된 하나의 컬럼에 담는다. (`max-width: 700px; margin: 0 auto;`)
- **폰트**: 한글 가독성이 좋은 폰트를 쓴다. (Pretendard 우선, 없으면 시스템 기본 한글 폰트로 대체 — `guides/image-guide.md`와 같은 폰트 선택 기준)
- **이미지**: 본문 폭에 맞춰 자동으로 리사이즈한다. (`img { max-width: 100%; height: auto; }`) 원본 비율은 유지한다.
- **위계**: 제목(H1) → 소제목(H2) → 본문(p)의 크기·굵기 차이가 한눈에 보이게 한다. H1이 가장 크고 굵게, H2는 그보다 작지만 본문보다 뚜렷하게 굵게, 본문은 읽기 편한 줄 간격(line-height 1.7~1.9 권장)을 준다.
- **인용/강조 요소**: `draft.md`에 인용 블록(`>`)이나 구분선(`---`)이 있으면 각각 시각적으로 구분되게 스타일을 준다. (인용은 왼쪽 선+연한 배경, 구분선은 옅은 가로줄)
- **배경**: 흰 배경 기본, 텍스트는 짙은 회색~검정 계열로 대비를 충분히 준다. (본문은 밝은 바탕에서 읽는 환경을 가정한다 — 어두운 테마의 이미지 자산과는 별개다.)
- **모바일 대응은 필수로 하지 않는다.** 이 파일은 로컬에서 브라우저로 열어 보는 미리보기 용도다. 다만 뷰포트가 좁아도 본문이 지나치게 깨지지 않을 정도면 충분하다.

---

## 5. 산출물

- `output/[주제]/final.md` — draft.md와 동일한 내용의 검토용 마크다운
- `output/[주제]/final.html` — 네이버 블로그 본문 스타일을 흉내 낸 시각 미리보기 (이미지 포함, 폭 700px)
- `blog/blog-log.json` — 발행 기록 추가(또는 갱신). 통합HUB 허브의 "블로그 자동화" 도구가 이 파일을 읽는다.

---

## 6. 마지막에 할 일

작업을 마치면 사용자에게 **`final.html`을 브라우저로 직접 열어서 확인해 보라고 안내한다.** (파일 경로를 그대로 알려준다.) 이 에이전트는 브라우저를 대신 실행하지 않는다.

---

## 7. 최종 체크리스트

- [ ] `draft.md`에 `[IMAGE: ...]` 형태의 미치환 마커가 남아 있지 않다.
- [ ] `final.md`가 `draft.md`와 같은 내용을 담고 있다. (문장·구조를 임의로 고치지 않았다.)
- [ ] `final.md`의 이미지 경로가 모두 `output/[주제]/images/` 안에 실제로 존재한다.
- [ ] `final.html`의 본문 폭이 약 700px로 중앙 정렬되어 있다.
- [ ] `final.html`의 이미지가 본문 폭에 맞춰 자동 리사이즈된다.
- [ ] 제목·소제목·본문의 글자 크기·굵기 위계가 명확하다.
- [ ] `blog/blog-log.json`에 이번 글의 발행 기록이 추가(또는 같은 id면 갱신)됐다.
- [ ] `blog-log.json`에 원래 있던 다른 글 기록이 하나도 사라지지 않았다. (배열을 통째로 덮어쓰지 않았다.)
- [ ] 사용자에게 `final.html`을 브라우저로 열어 보라고 안내했다.
