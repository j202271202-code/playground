# 클로드 코드 핵심 기능 5가지: 왜 다들 이 도구로 넘어가나

## 서론: 터미널 앞에서의 변화

코드를 짜다가 막힌 부분을 설명하느라 채팅창에 코드를 복사해 붙이고, 답을 받아서 다시 에디터에 옮기는 과정을 반복해 본 경험이 있을 겁니다. 흔히 AI 코딩 도구는 "자동완성을 조금 더 똑똑하게 해주는 것" 정도로 생각하지만, 클로드 코드는 이 과정 자체를 다르게 설계한 도구에 가깝습니다. 터미널 안에서 파일을 직접 읽고 고치고 실행까지 하기 때문입니다. 이 글에서는 클로드 코드를 실무에서 쓸 때 체감되는 핵심 기능 5가지를 살펴봅니다.

## 1. 파일 시스템 직접 접근: 복붙 없는 작업

클로드 코드의 가장 기본적인 차이는 코드를 **직접 읽고 씁니다**는 점입니다. 일반 챗봇은 사용자가 붙여 넣은 코드 조각만 볼 수 있지만, 클로드 코드는 프로젝트 폴더 안의 파일을 탐색하고, 필요한 파일을 열어서 맥락을 파악한 뒤 수정 사항을 그 자리에 반영합니다.

다만 이 방식은 프로젝트 구조가 클수록 어떤 파일을 먼저 읽을지 판단하는 과정이 길어질 수 있다는 한계도 있습니다. 그래서 `CLAUDE.md` 같은 안내 파일을 함께 두면, 탐색 시간을 줄이고 더 정확한 맥락으로 작업을 시작할 수 있습니다.

## 2. 터미널 명령 실행: 테스트와 실행까지 한 흐름으로

두 번째 핵심 기능은 **터미널 명령을 직접 실행**하는 능력입니다. 코드를 고친 뒤 "이 수정이 맞게 동작하는지" 확인하려면 보통 사람이 빌드하고 테스트를 돌려야 합니다. 클로드 코드는 이 단계까지 포함해서, 수정 → 실행 → 에러 확인 → 재수정의 순환을 스스로 반복할 수 있습니다.

> 코드를 짜고 끝나는 게 아니라, 돌려보고 틀리면 고치는 과정까지가 한 묶음인 셈입니다.

물론 실행 권한을 어디까지 허용할지는 사용자가 정할 수 있습니다. 파일 삭제나 되돌리기 어려운 명령은 실행 전에 확인을 받도록 설정하는 편이 안전하다는 의견이 많습니다.

## 3. 멀티파일 작업과 계획 수립: 큰 작업을 쪼개는 방식

세 번째는 **여러 파일에 걸친 작업을 계획하고 순서대로 처리**하는 기능입니다. 기능 하나를 추가하려면 보통 설정 파일, 로직 파일, 테스트 파일을 모두 건드려야 하는데, 클로드 코드는 이런 작업을 먼저 계획으로 정리한 다음 단계별로 실행합니다.

복잡한 작업일수록 먼저 계획만 세우고 사용자에게 확인받는 방식(Plan 모드)이 유리합니다. 계획 단계에서 방향이 틀렸다는 걸 미리 걸러내는 것이, 다 고친 뒤에 되돌리는 것보다 비용이 적게 들기 때문입니다.

## 4. 기억과 맥락 유지: 매번 설명을 반복하지 않는 구조

네 번째 기능은 **작업 맥락과 사용자 선호를 기억**하는 구조입니다. `CLAUDE.md` 파일이나 메모리 기능을 통해, 이 프로젝트에서는 어떤 규칙을 지켜야 하는지, 사용자가 이전에 어떤 방식을 선호했는지를 다음 대화에서도 이어받을 수 있습니다.

이 기억은 완벽하지 않습니다. 오래된 정보가 남아 있으면 실제 코드 상태와 어긋날 수 있어, 중요한 추천을 하기 전에는 파일을 다시 확인하는 절차가 함께 필요하다는 점도 알아 둘 만합니다.

## 5. 서브에이전트와 작업 분담: 혼자 다 하지 않는 구조

다섯 번째는 **특정 작업을 별도 에이전트에 위임**하는 기능입니다. 코드베이스를 넓게 탐색해야 하는 조사나, 보안 검토처럼 성격이 다른 작업은 전용 서브에이전트에게 맡기고, 메인 작업 흐름은 본래 목표에 집중하는 방식입니다.

이렇게 역할을 나누면 한 대화창에 모든 탐색 결과가 쌓여 맥락이 흐려지는 문제를 줄일 수 있습니다. 다만 서브에이전트는 이전 대화를 기억하지 못하므로, 위임할 때 필요한 맥락을 충분히 전달해야 한다는 조건이 붙습니다.

## 결론

클로드 코드의 핵심은 어느 한 기능이 뛰어나다는 데 있지 않고, 읽기·실행·계획·기억·위임이 하나의 작업 흐름으로 묶여 있다는 데 가깝습니다. 도구를 하나 더 쓰는 일이 아니라, 반복 작업을 맡기고 판단이 필요한 부분에만 집중하는 일입니다.
